# 第 0 阶段：项目怎么组织

这一阶段没有数据和模型，做的是“地基”：文件放哪、用哪套 Python、配置写哪、怎么防止改坏、怎么防止丢数据。

## 1. 虚拟环境：项目专用的一套 Python

电脑上本来就装了 Python。项目里又建了一个 `.venv` 文件夹，里面是这个项目专用的一套 Python 和库。

为什么要单独一套：不同项目需要的库版本可能不同。全装在电脑的 Python 里，给 A 项目升级 pandas，B 项目可能就坏了。
虚拟环境把每个项目隔开。

所以运行项目的程序时，要用 `.venv\Scripts\python`，不要直接打 `python`（那是电脑上的那一套，里面没装这些库）。

## 2. 依赖库和版本锁定

| 文件 | 内容 | 用途 |
|---|---|---|
| `requirements.txt` | 要哪些库、各自做什么 | 人看的清单 |
| `requirements-lock.txt` | 每个库的精确版本，例如 `pandas==3.1.0` | 换电脑时装出一模一样的环境 |

为什么要锁版本：库升级后，同一段代码的结果可能变。回测成绩变了，要能分清是模型改了还是库变了。

这次装的库：

| 库 | 做什么 |
|---|---|
| pandas | 处理表格：读 CSV、筛选、分组统计。后面用得最多 |
| numpy | 数值计算，pandas 的底层 |
| scipy | 统计分布（泊松分布）和参数拟合（Dixon-Coles 要用） |
| requests | 下载网页和文件 |
| PyYAML | 读配置文件 |
| pytest | 跑自动检查 |

## 3. 配置文件：数字和路径不写死在代码里

`config/settings.yaml` 里放着路径、赛季用途、联赛代码、爬虫间隔等。代码要用时从这里读。

好处：要改“期末考试是哪两个赛季”、“备份放哪”，只改这一个文件，不用翻代码；以后搬到云服务器也只改这里。

密钥（推送服务的密码之类）另放 `config/secrets.yaml`，这个文件不上传 GitHub。仓库是公开的，密钥上传了谁都能看到。

赛季用途已经写成代码规则：

| 赛季（开始年份） | 用途 |
|---|---|
| 2023 及以前（2023/24 及以前） | 开发 |
| 2024、2025 | 期末考试 |
| 2026 起 | 上线后 |

## 4. Git：每次改动都有记录

Git 记录项目里每个文件的每次改动。每做完一段就“提交”一次（相当于存一个带说明的存档点），再“推送”到 GitHub。

- 改坏了：可以退回任何一个存档点。
- 想知道某处为什么这样写：可以查是哪次改的、改动说明是什么。
- `.gitignore` 列出不上传的东西：数据、数据库、日志、密钥、虚拟环境。

## 5. 备份：Git 不备份数据

Git 只管代码和文档。数据库和爬到的页面不进 Git（太大，而且仓库公开），所以另有每日备份：

- 数据库每天复制一份，文件名带日期，保留最近 30 天。
- 爬到的原始页面只复制新增的文件。原始页面只增不改，旧的不会变，不用每天整份复制。
- 备份放在 `D:\足球预测系统_备份`，在项目文件夹外面：误删项目文件夹时备份还在。硬盘坏了会一起丢，以后再换位置。

备份已经登记进 Windows 任务计划程序，名字叫“足球预测_每日备份”，每天 03:30 跑；那时电脑关着的话，开机后补跑。

## 6. 自动检查：改代码后跑一遍

`tests/` 文件夹里是自动检查。例如“连续备份 5 天、只保留 3 天，最后应该剩下第 3、4、5 天的备份”。
程序结果和预期不一样就报错。

现在只有 11 项，后面每加一块计算（去水、亚盘结算、比分矩阵），都会加对应的检查。

## 你可以自己运行的命令

在项目文件夹打开终端（文件夹空白处右键 →“在终端中打开”），依次运行：

环境检查（8 项，应该全部“通过”）：

```bash
.venv\Scripts\python -m src.jobs.check_env
```

自动检查（应该显示 11 passed）：

```bash
.venv\Scripts\python -m pytest
```

手动跑一次备份（现在还没有数据库，会显示“跳过”）：

```bash
.venv\Scripts\python -m src.jobs.backup
```
