# 第 2 阶段（四）：泊松、Dixon-Coles、负二项（模型步骤 1–3）

这一篇讲第 2 阶段的模型步骤 1–3：先用“进攻力、防守力、主场优势”估每队的预期进球（泊松），
再修正小比分（Dixon-Coles，简称 DC），最后试“进球更分散”的负二项。三个其实是同一个程序 `src/models/goals.py` 的三种开关。
结果：留下 dc，胜平负 log loss 0.98921，比第 0 步最好的 elo_gd（0.99173）好 0.0025。

## 1. 直觉：先猜进球，再算概率

第 0 步的 Elo 直接猜“谁赢”。这一步换个思路：先猜两队**各进几个球**，再从进球数推出所有玩法。

- 每队有两个数：进攻力 a（进得多不多）、防守力 d（丢得多不多）。
- 主队多一个主场优势 home。
- 两队的预期进球 λ（读作 lambda，意思是“平均会进几个”）由这几个数算出来。
- 知道 λ 以后，用泊松分布算“进 0 个、1 个、2 个……”的概率，两队拼起来就是一张**比分矩阵**（0–10 球，11 × 11 格，加起来是 1）。
- 胜平负、大小球、双方进球、亚盘，全部从这张矩阵加格子得到（加法见“第2阶段_计算校验”）。

好处：一个模型就能出所有玩法，而且各玩法之间不会互相矛盾。

## 2. 关键公式

**预期进球**（log 是自然对数，e 的多少次方）：

- log λ主 = mu + home + a主 − d客
- log λ客 = mu + a客 − d主

| 符号 | 意思 |
|---|---|
| mu | 这个联赛的平均进球水平 |
| home | 主场优势 |
| a主、a客 | 主队、客队的进攻力（越大进得越多） |
| d主、d客 | 主队、客队的防守力（越大丢得越少，所以前面是减号） |

例（数字是编的，只为演示）：mu = 0.1、home = 0.25、a主 = 0.2、d客 = −0.1，
log λ主 = 0.1 + 0.25 + 0.2 + 0.1 = 0.65，λ主 = e^0.65 ≈ **1.92** 个球。

**泊松概率**：一队预期进 λ 个，正好进 k 个的概率 = λ^k × e^(−λ) ÷ k!。
两队当成互相独立，比分 i:j 的概率 = P主(i) × P客(j)。

**DC 修正**：真实比赛里 0:0、1:1 比“两队独立”算出来的多。DC 只改 4 个小比分格子，用一个参数 ρ（rho）：

| 比分（主:客） | 乘上 |
|---|---|
| 0:0 | 1 − λ主·λ客·ρ |
| 0:1 | 1 + λ主·ρ |
| 1:0 | 1 + λ客·ρ |
| 1:1 | 1 − ρ |

ρ 是负数时，0:0 和 1:1 变大，0:1 和 1:0 变小，平局变多。这 4 格加减正好抵消，总进球数的分布不变，所以大小球不受影响。

**时间衰减**：越久以前的比赛权重越小。权重 = 0.5^(距今天数 ÷ 半衰期)。半衰期 365 天：一年前的比赛算一半，两年前算 1/4。

**收缩（ridge）**：拟合时多一项惩罚 ridge/2 × (a − 中心)²，把场次少的队的实力往“中心”拉，防止几场比赛就把一队估得很极端。
升班马的中心不是 0，是往年升班马的平均水平（settings.yaml 里的 promoted 设为 −0.2）。

**负二项**：泊松的方差等于平均数（方差 = λ）。负二项多一个 α：方差 = λ + αλ²，α > 0 时进球更“分散”，大比分更多。α = 0 就退回泊松。

## 3. 手算一遍 DC

设 λ主 = 1.5、λ客 = 1.0、ρ = −0.1（演示用的数）。

| 比分 | 泊松 | 乘的数 | DC 后（归一前） |
|---|---|---|---|
| 0:0 | 0.0821 | 1 − 1.5 × 1.0 × (−0.1) = 1.15 | 0.0944 |
| 0:1 | 0.0821 | 1 + 1.5 × (−0.1) = 0.85 | 0.0698 |
| 1:0 | 0.1231 | 1 + 1.0 × (−0.1) = 0.90 | 0.1108 |
| 1:1 | 0.1231 | 1 − (−0.1) = 1.10 | 0.1354 |

4 格合计：泊松 0.4104，DC 后 0.4104，总和没变。平局（0:0 + 1:1）从 0.2052 变成 0.2298，多了 0.0246。
程序注释里的公式：平局变化 = −2·ρ·c，c = λ主·λ客·e^(−λ主−λ客) = 0.1231，−2 × (−0.1) × 0.1231 = 0.0246，对上了。

## 4. 项目里怎么做的

| 内容 | 位置 |
|---|---|
| 三个模型（开关 dc、nb） | `src/models/goals.py` |
| 回测入口（另外存比分矩阵，算比分 log loss 和进球分布核对） | `src/models/goals_backtest.py` |
| 设置：窗口 1461 天（4 年）、半衰期 365 天、收缩 3、升班马中心 −0.2、往年 3 个赛季 | `config/settings.yaml` 的 `goals` |

- 每个联赛一套参数，每周拟合一次（找让“过去比赛的比分出现概率”最大的那组参数，用 L-BFGS-B 方法）。
- 数据只从取数层拿，截止时间以前的比赛才进拟合。
- ρ 的范围：每场 4 个小比分格子乘的数至少留 5%（程序里 TAU_MIN = 0.05），另外 |ρ| 不超过 0.3（RHO_LIMIT）。
  这条是跑出问题后加的，见第 6 节误区 4。
- 回测范围：五大联赛 2005/06–2023/24，T-24，34,519 场；比较用按周成块 bootstrap、95% 区间。
- 跑之前先把要试的设置和判定规则写进需求文档第 4 节“步骤 1–3 事先定的比较”，提交后再跑。

## 5. 结果和怎么读

先说怎么读 log loss：每场比赛记 −log(实际发生那个结果的概率)，再求平均。越小越准。
例：实际主胜，你给主胜 45%，这场记 −log(0.45) = 0.799；只给 30%，记 1.204。

**步骤 1：泊松**

| 模型 | 胜平负 log loss | 比分 log loss |
|---|---|---|
| frequency_poisson（第 0 步） | 1.0657 | 2.9944 |
| elo_gd（第 0 步最好） | 0.9917 | — |
| poisson（收缩 3） | 0.9897 | 2.8880 |
| poisson_ridge1 | 0.9911 | 2.8931 |
| poisson_ridge10 | 0.9896 | 2.8832 |

- poisson 比 elo_gd 更准：差 −0.0020，区间 −0.0035 到 −0.0005（整个在“更准”一边才算数），19 个赛季里 14 个更好。
- 收缩 1 更差；收缩 10 胜平负没差别（区间 −0.0006 到 +0.0003），按规则留 3。
- 泊松预测平局 24.1%，实际 25.7%：少估了约 1.5 个百分点（按没四舍五入的数），正是 DC 要修的。

**步骤 2：DC**

| 模型 | 胜平负 log loss | 比分 log loss | 平局 预测 / 实际 |
|---|---|---|---|
| poisson | 0.98974 | 2.8880 | 24.1% / 25.7% |
| dc（半衰期 365 天） | 0.98921 | 2.8873 | 25.7% / 25.7% |
| dc_hl90 | 0.99854 | 2.9115 | |
| dc_hl180 | 0.99113 | 2.8934 | |
| dc_hl730 | 0.99025 | 2.8885 | |
| dc_nodecay（2 年不衰减） | 0.99260 | 2.8959 | |

- dc 比 poisson：差 −0.00054（区间 −0.00099 到 −0.00008）。差得很小，但区间整个在“更准”一边，按规则保留 DC。
- 半衰期 90 天最差：一个半赛季以前的比赛几乎不算，有效场数太少。别的衰减也都比 365 天差。

**步骤 3：DC + 负二项**：dcnb 和 dc 几乎一样（0.989205 对 0.989206）。α 几乎每次都拟合到 0，也就是退回泊松。
原因：五大联赛的总进球方差，预测 2.907、实际 2.786，进球本来就比泊松**更集中**，负二项只能让它更分散，帮不上。按规则不保留。

**和市场比**：平博收盘（21,733 场）是 0.96293，dc 还差约 0.02。0.02 是什么概念：
把 log loss 换回“平均给实际结果多少概率”（e^(−log loss)，只是一个粗略的感觉），dc 约 37.2%，平博约 38.2%。
差 1 个百分点左右，但每场都差，几万场下来就是很稳定的差距。

## 6. 常见误区

1. **只看差多少，不看区间。** dc 比 poisson 只好 0.00054，看起来像噪声。判断靠的是按周 bootstrap 的 95% 区间是否整个在一边。
   反过来，收缩 10 的比分 log loss 更好，但胜平负区间跨过 0，按事先定的规则也不换。
2. **跑完再改规则。** 9 组设置是跑之前写进需求文档的，跑完不加组。跑完再挑“看着好的”，等于在开发赛季上反复试，结果会偏乐观。
   这些比较也没做多重比较修正，所以最终以期末考试为准。
3. **偷看未来。** 拟合只能用截止时间以前的比赛。“每周拟合一次”是用这一周开始前的数据，预测这一周的比赛；
   如果把整个赛季一起拟合再回头预测，模型就看到了答案。期末考试的 2024/25、2025/26 两季在开发模式下锁住（取数时直接报错），
   就是为了让最终成绩来自从没“看过”的比赛。
4. **以为公式永远成立。** 第一次跑步骤 2 时，西甲 2010/11 半衰期 90 天的一组，ρ 卡在 −0.236，
   巴萨主场 0:1 那格乘的数 1 + 4.7 × (−0.236) 小于 0，概率成了负数，拟合程序报错。改法是限制 ρ 的范围（第 4 节），第一次的结果作废重跑。
5. **以为“更复杂 = 更好”。** 负二项多一个参数，结果没有任何好处；衰减越快也不是越“跟得上”，而是更差。

## 7. 小练习

**练习 1**：mu = 0.1、home = 0.25、a主 = 0.2、d客 = −0.1。主队预期进几个球？如果客队防守变好，d客 = +0.1，又是多少？

<details><summary>答案</summary>

log λ主 = 0.1 + 0.25 + 0.2 − (−0.1) = 0.65，λ主 = e^0.65 ≈ **1.92**。
d客 = 0.1 时：0.1 + 0.25 + 0.2 − 0.1 = 0.45，λ主 = e^0.45 ≈ **1.57**。防守力是减号，对手防守越好，你进得越少。

</details>

**练习 2**：λ主 = 1.5、λ客 = 1.0。把 ρ 从 −0.1 改成 −0.2，平局概率大约多多少？大 2.5 球的概率会变吗？

<details><summary>答案</summary>

平局变化 = −2·ρ·c，c = 1.5 × 1.0 × e^(−2.5) ≈ 0.1231。ρ = −0.2 时 −2 × (−0.2) × 0.1231 ≈ **+0.049**（比泊松多约 4.9 个百分点，ρ = −0.1 时是 2.5 个）。
大 2.5 球**不变**：4 个格子的总进球都在 0–2 之间，加减抵消，“总进球 0–2”这一档合起来不变。

</details>

**练习 3**：半衰期 365 天，半年前（182 天）的比赛权重多少？把半衰期改成 90 天，一年前的比赛权重多少？为什么 90 天反而更差？

<details><summary>答案</summary>

0.5^(182 ÷ 365) ≈ **0.71**；0.5^(365 ÷ 90) ≈ **0.06**。
90 天时一年前的比赛几乎不算，有效场数太少，估出的实力容易被最近几场的运气左右，所以 log loss 更差（0.99854 对 0.98921）。

</details>

**练习 4**：有人把 2005–2023 全部比赛一次拟合出每队实力，再用这些实力“预测”2015 年的比赛，log loss 比 dc 好很多。能说明他的模型更好吗？

<details><summary>答案</summary>

不能。拟合时用到了 2015 年这些比赛本身和之后的比赛，等于先看了答案。
正确的做法是滚动：每周只用这一周之前的比赛拟合。取数层就是为了让这种错误写不出来。

</details>

**练习 5**：负二项的方差 = λ + αλ²。λ = 1.4、α = 0.1 时方差是多少？为什么五大联赛的数据让 α 拟合到 0？

<details><summary>答案</summary>

1.4 + 0.1 × 1.96 = **1.596**（泊松是 1.4）。
因为实际进球比泊松更集中（总进球方差预测 2.907、实际 2.786），α > 0 只会让分布更分散、离实际更远，所以拟合把 α 压到下限 0。

</details>
