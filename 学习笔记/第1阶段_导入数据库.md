# 第 1 阶段（中）：清洗进数据库、数据质量检查

上一段把 football-data 的 CSV 下载下来、清点了每一列（见《第1阶段_数据清点》）。
这一段把它们清洗成统一格式，放进数据库 `data/football.db`，再自动检查一遍数据有没有问题。

## 1. 结果

| 项目 | 数量 |
|---|---|
| 文件 | 330 个（西乙 1993–95 三个文件其实是西甲，去掉了） |
| 比赛 | 125,792 场 |
| 赔率 | 1,887,117 组（一组 = 一家公司 × 一种玩法 × 赛前或收盘） |
| 球队 | 421 支 |
| 导入用时 | 约 1.5 分钟 |
| 数据库大小 | 约 180 MB |

## 2. 为什么要放进数据库，不直接读 CSV

- CSV 是 330 个文件，每个文件列不一样（早年的平均赔率叫 BbAvH，后来叫 AvgH）。每次用都要重新处理一遍，容易出错。
- 数据库里只有一种格式：比赛一张表，赔率一张表，球队一张表。以后国内网站的数据进来也是同样的表，模型不用管数据从哪来。
- 数据库能直接回答问题，例如“英超所有比赛主场赢了多少”，一句查询就出来（见第 6 节）。

## 3. 六张表

| 表 | 一行是什么 | 为什么单独一张 |
|---|---|---|
| teams | 一支球队 | 统一的球队编号。以后中文名也放这里 |
| team_names | 一种队名写法 → 球队编号 | 不同网站、不同年份同一支队写法不一样 |
| matches | 一场比赛 | 统一的比赛编号，其他表都用这个编号 |
| match_sources | 这场比赛在哪个文件出现过、什么时候下载的 | 以后同一场比赛会从好几个网站来 |
| match_stats | 一个来源给的比分和统计 | 两个网站的比分对不上时，两份都留着 |
| odds | 一家公司一种玩法一个时点的赔率 | 一场比赛有几十组赔率，放在比赛表里会有几百列 |

这种“一件事一张表，用编号连起来”的做法叫**规范化**。好处是同一个信息只存一次，改的时候不会改漏。

## 4. 清洗时做了哪些换算

| 原始数据 | 换成 | 例子 |
|---|---|---|
| 两种日期写法 | 统一的 `年-月-日` | `25/08/07` 和 `25/08/2007` 都变成 `2007-08-25`；两位年份 93 是 1993，07 是 2007 |
| 英国当地时间 | 标准时间（UTC） | 英超 2025-08-15 的 20:00 是夏令时，标准时间 19:00；2026-01-08 的 20:00 是冬令时，标准时间还是 20:00 |
| 队名不同写法 | 同一个球队编号 | `M'Gladbach` 和 `M'gladbach` 是同一支 |
| 亚盘“半一” | 平均数 | `-0.5,-1` → `-0.75`（主让半一） |
| 赔率 0 | 不要 | 0 是“没有数据”，不是赔率。共 42 个 |
| 亚盘盘口 1.28、-0.390625 | 当作空 | 盘口只能是 0.25 的倍数，这些多半是把赔率录进了盘口列 |

为什么时间一定要换成标准时间：以后要判断“预测时（开赛前 24 小时）能不能看到这条数据”。
英国时间一年里有半年差 1 小时，不统一的话，会有一半的比赛差 1 小时，判断“能不能看到”就会错。

| 赛果和比分对不上、主客队同一支、同一天踢两场、日期超出赛季 | 没有 | — |
| 赔率抽水异常 | 每家公司几组到一百多组 | 见下面 |

### 抽水：用赔率检查赔率

把一场比赛三个结果的赔率取倒数加起来，就是公司给的三个概率之和。例如 2.0 / 3.5 / 4.0：

```
1/2.0 + 1/3.5 + 1/4.0 = 0.500 + 0.286 + 0.250 = 1.036
```

比 1 多出来的 0.036（3.6%）就是公司的抽水。用实际数据算出来：

| 公司 | 胜平负抽水（平均） |
|---|---|
| 平博 Pinnacle | 2.8% |
| Bet365 | 6.9% |
| Interwetten | 9.8% |
| Betfair 交易所 | 约 1%（玩家互相挂单，交易所另收佣金） |
| 多家最高 | 约 1%，常常是负数（倒数之和低于 1） |

- 普通公司的倒数之和一定大于 1，否则谁都能稳赚。低于 1 或者高出很多，多半是录错了。
- “多家最高”每个结果各挑一家给得最高的，三个数可能来自三家公司，所以低于 1 很正常。第一次检查时没区分，报了 1.6 万条“异常”，
  其实是检查规则错了。现在三类数据各用一个范围（数字在 `config/settings.yaml`）。
- 平博抽水最低，价格最接近“真实概率”，这就是需求文档里用平博收盘当标杆 1 的原因。

## 6. 第一次用数据库回答问题：主场优势

全部 125,792 场：主胜 45.3%，平 28.0%，客胜 26.7%。主场优势是真实存在的。

疫情那一季（2020/21，大部分比赛没有观众）：主胜降到 40.8%；之前五季 44.4%，之后 43.3%。
这说明主场优势有一部分来自观众。以后建模型时，2020/21 这一季的主场优势要单独看，不然会把模型带偏。

## 小练习

1. 赔率 1.50 / 4.00 / 6.00，抽水是多少？去掉抽水后主胜的概率是多少？
2. 为什么比赛编号要保证“重新导入也不变”？
3. 一场英超在 2025-03-29（英国 3 月 30 日才换夏令时）15:00 开球，标准时间是几点？如果在 2025-04-05 呢？
4. 法乙 2019/20 只有 280 场。用这个赛季算“每队平均每场进球”有问题吗？算“赛季积分排名”呢？

<details>
<summary>答案</summary>

1. 1/1.5 + 1/4 + 1/6 = 0.667 + 0.250 + 0.167 = 1.083，抽水 8.3%。最简单的去水方法是按比例缩小：主胜 0.667 / 1.083 = 61.5%。
2. 以后的预测、机器人注单都用比赛编号记“这是哪场比赛”。重导后编号变了，旧的预测就对不上比赛了。
3. 3 月 29 日还是冬令时，15:00 就是标准时间 15:00。4 月 5 日是夏令时，标准时间 14:00。
4. 平均每场进球没问题，按场数平均，少踢的场次不影响。积分排名有问题：各队踢的场数不一样（有的 28 场，有的 27 场），总积分不能直接比，要用场均积分。
